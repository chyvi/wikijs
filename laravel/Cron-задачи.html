Таблица прочих кронов (ISP, бэкапы, мониторинг, логирование и т.д.)

Зависимости cron-заданий, генерация схемы

Каждая cron-задача оформляется через аннотацию @jaco.cron в PHP-комментариях. Эта аннотация содержит JSON с описанием задачи: что она делает, от чего зависит, с какими таблицами/файлами работает, когда запускается, к какой группе принадлежит и на какую страницу-диаграмму (page) попадает. Имеется дефолтная страница-диаграмма для задач, не попавших никуда (не указали page).

Парсинг осуществляется по файлам каталога app/Http/Controllers/Crone

После парсинга аннотаций выполняется генерация интерактивной Mermaid диаграммы, отражающей связи между задачами, таблицами и файлами. Подробнее с Mermaid можно ознакомиться по ссылке

Пример аннотации

/**
 * @jaco.cron {
 *   "id": "crone_count_active_accounts",
 *   "type": "data",
 *   "group": "Пользователи",
 *   "depends_on": ["cron_check_site_users_stat_v2"],
 *   "reads": [
 *     "jaco_site_rolls.site_orders_new",
 *     "jaco_main_rolls.site_users"
 *   ],
 *   "writes": [
 *     "jaco_site_rolls.active_accounts",
 *     "jaco_site_rolls.active_accounts_city",
 *     "jaco_site_rolls.active_accounts_all"
 *   ],
 *   "time": "после cron_check_site_users_stat_v2",
 *   "schedule": "ежедневно",
 *   "description": "Агрегирует данные о заказах пользователей по точкам и городам: активность, регистрация, сумма и число заказов"
 * }
 */

Расшифровка полей:

Рекомендации:

  • Для таблиц указывайте schema.table, чтобы избежать коллизий.
  • Для файлов начинайте путь с public/, storage/, s3_ и т.п., чтобы парсер распознал тип (file).
  • Не используйте * в reads/writes — это блокируется.
  • Следите за балансом: слишком много reads/writes может захламить визуализацию — группируйте их, например jaco_rolls_*.orders для таблиц orders разных точек.

Для запуска используйте artisan-команду. Либо по крону запускается в 04:00 ежедневно. По-умолчанию всё логируется через Helper в обычных для кронов логах. Доступен режим дебага php artisan cron:generate-diagram --debug для вывода логов в консоль найденных аннотаций, возможных ошибок JSON, диагностических сообщений
