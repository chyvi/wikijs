Используется модуль L5-Swagger, на момент обращения (05/02/25) он поддерживает версию Laravel c 7.x по 11.x. и OpenApi 3.0.x В целом по OpenApi примеров можно много найти, но по L5-Swagger аннотации документация скудная. Приветствуется дополнять данную статью примерами для разных заковыристых запросов и ответов))

Работает следующим образом: мы ручками прописываем аннотации по году, жмём генерацию в терминале, модуль генерирует json-файл с описанием запросов и рендерит его в браузере по дефолту по пути project/api/documentation. Json-файл можно поправить руками, если разбираетесь в синтаксисе, и он отобразится в браузере, но любая последующая генерация уберёт все такие изменения. Синтаксис аннотаций не сложный, но требует аккуратности и внимательности. Если всё норм прописать, то запросы и ответы в браузере отлично работают через модуль. В целом рекомендую использовать Postman в дополнение ко всему

Установка

Устанавливаем через composer. Далее вбиваем команду $ php artisan vendor:publish --provider "L5Swagger\L5SwaggerServiceProvider" . Если в проекте аннотаций нет, то команда $ php artisan l5-swagger:generate выдаст ошибку об отсутствии необходимых аннотаций.

Настройка и синтаксис

Есть два пути: 

  • прописывать все аннотации по месту применения, то есть прям в контроллерах, классах и методах. Это удобно, но приводит к километровым комментариям в коде;
  • дублировать необходимые контроллеры, классы и методы в отдельной папке (без кода, только названия) app/Http/Controllers/Swagger. Папку можно использовать любую, название Swagger было выбрано для осмысленности наименования. Рабочий код так не тронут, всё в одном месте. Недостаток - нужно следить за соответствием аннотации и рабочего кода, если код будет меняться (названия методов, принимаемые параметры и т.д.)

В нашем случае используется второй способ. Там создаём основной сваггеровский контроллер с базовой аннотацией. Вся аннотация заключается в начальные /** и конечные */, как в примере ниже:

/**
 * @OA\Info(
 *      title="Jacochef API",
 *      version="1.0.0"
 *  ),
 * @OA\PathItem (
 *      path="/api/"
 *  ),
 */

@OA\Info - справочная информация, которая отображается на странице документации. В title и version можно указать любой произвольный текст. @OA\PathItem содержит path путь к api. Табуляция и отступы произвольные, как удобно, можно всё в одну строку записать. Но внимательно с запятыми, они обязательно должны стоять после скобок, при перечислении параметров и т.д.

В config/l5-swagger.php описываются основные настройки. В целом всё понятно по комментам, остановлюсь на некоторых моментах:

  1. В ‘documentations’ => [ ‘default' => [ ‘routes’ … ],] прописан путь api/documentation - это путь, по которому доступна наша документация в браузере. Можно поменять на любой другой. Рядом есть title, названия генерируемого файла json и т.д.
  2. Авторизация securitySchemes. Хорошо работает с jwt, но у нас доступ через apiKey (свой токен узнайте при авторизации через браузер в консоли разработчика). ‘Type’ => ‘apiKey’, ‘description’ произвольное, ‘name’ => ‘login’, ‘in’ => ‘query’. Это наши настройки. Так же выбрана опция persist_authorization в значение true, чтобы в браузере при перезагрузке страницы не разлогиниваться (по дефолту false).

Всё, можно выполнить $ php artisan l5-swagger:generate и проверять в браузере работу

 

Как работать, примеры

Есть GET, POST, PUT, DELETE, PATCH запросы. Запросы с параметрами и без. Если предусмотрено несколько видов ответов, то желательно их перечислять, по типу 200 OK, 401 отсутствия авторизации, 500 внутренней ошибки сервера и т.д. Если ответ придёт не документированный, то в браузере так и будет написано. Если запрос требуется закрыть авторизацией, то это нужно прописать аннотацией security с ссылкой на нашу схему:

*    @OA\Response(
*          response=401,
*          description="Unauthorized",
*    ),
*    @OA\Response(
*         response=500,
*         description="Internal Server Error",
*     ),
*    security={
*             {"jaco_security": {}}
*    }

Запрос, закрытый авторизацией, будет помечен в браузере значком замочка. Открытый серого цвета, если мы не авторизованы, и закрытый чёрного цвета после авторизации.

Параметры запроса описываются в @OA\Parameter(). Если нужно что-то отправить на сервер, то надо описать @OA\RequestBody(). Описать нужно таким образом, чтобы синтаксис данных (массива, например), выглядели точно так же, как в реальных условиях - сервер примет то, что мы описали и пришлёт ответ. Если данные отправляются с формы, то можно указать это в mediaType, например:

*    @OA\RequestBody (
*        @OA\MediaType(
*            mediaType="multipart/form-data",
*            @OA\Schema(
*                @OA\Property(property="data", type="object",
*                    @OA\Property(property="id", type="integer", example="96"),
*                ),
*            ),
*        ),
*    ),

@OA\Schema позволяет описать произвольный массив данных.

@OA\Response обязателен, по сути, ради этого мы и делаем всю работу здесь. Нужно описать аннотацию таким образом, чтобы данные (массив и т.д.), приходящие в ответ от сервера, выглядели так же, как мы описали в аннотации.

В @OA\Property в property указывается наименование поля (можно оставить пустым “” или же вовсе не указывать), тип type (integer, string, date и т.д. для данных и object, array для вложенных массивов и т.д.). Можно здесь указать example, можно не указывать, можно example прописать отдельно, как удобней, см. примеры, поваренную книгу и т.д. Если type указан как object, то внутрь @OA\Property можно вложить @OA\Property ещё раз. Уровень вложенности может быть любой. Если указали array, то нужно прописать @OA\Items, внутри которого уже будут @OA\Property и т.д. У @OA\Property массив идёт с фигурными скобками {}, у @OA\Items с квадратными []. Массив можно делать как ассоциативный, так и нет.

Пример Response с отдельным example:

*      @OA\Response(
*          response=200,
*          description="OK",
*          @OA\JsonContent(
*               @OA\Property (property="", type="array", @OA\Items(
*                   @OA\Property(property="id", type="integer"),
*                   @OA\Property(property="name", type="string"),
*                   @OA\Property(property="categories_id", type="integer"),
*                   @OA\Property(property="created_at", type="date"),
*                   @OA\Property(property="updated_at", type="date"),
*                   @OA\Property(property="delete", type="integer"),
*               )),
*               example={{
*                   {
*                       "id": 1,
*                       "name": "Children",
*                       "categories_id": 1,
*                       "created_at": "1980-01-01",
*                       "updated_at": null,
*                       "delete": 0,
*                   }
*               }}
*          ),
*      ),

Массив будет выглядеть так:

[
  [
    {
      "id": 1,
      "name": "Children",
      "categories_id": 1,
      "created_at": "1980-01-01",
      "updated_at": null,
      "delete": 0
    }
  ]
]

Примеры Patch и Delete запросов. В Patch отдаётся id, в обоих применяется аутентификация bearerAuth:

* @OA\Patch(
 *       path="/api/categories/{id}",
 *       summary="Обновление",
 *       tags={"Categories"},
 *       security={{ "bearerAuth": {} }},
 *       @OA\Parameter (
 *          description="ID категории",
 *          in="path",
 *          name="category",
 *          required=true,
 *          example=1,
 *      ),
 *      @OA\RequestBody (
 *          @OA\JsonContent (
 *              allOf={
 *                  @OA\Schema (
 *                      @OA\Property(property="id", type="integer", example=1),
 *                      @OA\Property(property="name", type="string", example="Children"),
 *                  )
 *              }
 *          ),
 *      ),
 *       @OA\Response(
 *           response=200,
 *           description="OK",
 *           @OA\JsonContent(
 *                @OA\Property (property="", type="array", @OA\Items(
 *                    @OA\Property(property="id", type="integer", example=1),
 *                    @OA\Property(property="name", type="string", example="Children"),
 *                    @OA\Property(property="categories_id", type="integer", example="1"),
 *                    @OA\Property(property="created_at", type="date", example="1980-01-01"),
 *                    @OA\Property(property="updated_at", type="date", example=null),
 *                    @OA\Property(property="delete", type="integer", example=0),
 *                )),
 *           ),
 *       ),
 *   ),
 *
 * @OA\Delete(
 *       path="/api/categories/",
 *       summary="Удаление",
 *       tags={"Categories"},
 *       security={{ "bearerAuth": {} }},
 *       @OA\Response(
 *           response=200,
 *           description="OK",
 *           @OA\JsonContent(
 *                @OA\Property (property="result", type="object", example=true),
 *           ),
 *       ),
 *   ),

Для описания массива ещё применяются allOf={} и oneOf={}
